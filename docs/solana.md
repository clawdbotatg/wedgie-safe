# Solana transfer qualification

Safe Signer authorizes a Swig smart account through a P‑256 key in the Trust M. The host's
fee payer signs the outer Solana transaction. The established Safe{Wallet} signing flow remains
available through its own key and protocol.

## Supported transfers

- **SOL** uses one System Program transfer with an on-device review of the source wallet,
  destination, and amount. The transaction limit is 10,000,000 lamports (0.01 SOL).
- **SPL** uses one legacy Token Program `TransferChecked` for the enrolled mint with six
  decimal places. The device shows the mint, destination token account, and amount. The
  transaction limit is 10,000,000 base units (10 tokens). Swaps, staking, NFTs, Token-2022,
  arbitrary instructions, and wallet-adapter message signing require separate integrations.
- **Networks** are local and devnet. The device chooses the review label and the key from
  the saved profile. The Swig message does not carry a cluster identifier, so the host must
  verify its genesis hash, executable, wallet address, and active role before using any
  public cluster. Keep keys separate between clusters. The host's spending role should grant
  only the programs and amounts needed for the enrolled wallet.

`hello` reports `solana_protocol: 1` when the cartridge is sealed with an initialized
Trust M, a 240×240 screen, and a ready Safe signer. `sol_status` returns the independently
saved profile for `local` or `devnet`. `sol_enroll` checks the two Swig PDAs and asks for a
physical press before binding or generating the test key. `sol_sign` reconstructs the message,
compares the host's expected digest, and requests physical review. Mainnet requests are refused
before profile reads or chip operations.

## Keys and recovery

KEY2 is reserved for the Ethereum Safe signer. Devnet uses KEY3 and the local validator
uses KEY4. The current cartridge refuses to generate a new Solana key over an occupied slot.
The local test wallet can adopt an existing KEY4 after proving its public key. Devnet requires
a fresh key. The stock Wedgie Secrets cartridge also uses KEY3, so plan device use before
installing it alongside a devnet signer.

Back up the public wallet address, network, mint, and role metadata locally and keep the
recovery authority separately. The device saves cannot restore the chip private key. Use a
disposable wallet on the target test cluster to rehearse a lost signer. Verify the recovery role
can add a replacement with the intended spending limits, revoke the former role, and retain the
wallet address and balances. Confirm the old role is inactive before signing again with the new
device. No export of the former spending key is needed.

## Review and release checks

1. Run `python3 -B tools/test-solana.py` and `./tools/mpy.sh` from this repository. Confirm the
   generated bytecode matches the reviewed source and uses the pinned MicroPython compiler.
2. Use disposable identities in the RP2040 emulator to sign Ethereum Safe, local SOL and SPL,
   and devnet-profile SOL and SPL. Check the returned digests and signatures independently,
   exercise red-button refusal, and verify both profiles survive reboot.
3. On the exact signed candidate, confirm the Ethereum identity and saves before and after
   installing. Verify local transfers and a devnet recovery with separate disposable wallet
   funds and exact reviewed recipients. The emulator establishes device protocol behavior.
   A prior release's hardware receipts establish the tested behavior of that release.
4. Mainnet qualification requires matching the live Swig executable to a reproducible build
   from the exact reviewed source, then testing the matched binary locally. Plan an isolated
   production signing slot or a separate device, independent recovery, explicit network
   binding, and hardware qualification before an owner reviews any mainnet enrollment or send.
   Leave the mainnet write guards in place until those gates pass.
